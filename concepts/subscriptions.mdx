---
title: Subscriptions
description: A customer's binding to a plan, from checkout to renewal and cancellation.
---

A **subscription** links one customer to one plan. It records the billing period, the currency, the seat count and the payment state. A customer can hold one live subscription per [product](/concepts/products). Every change is written to the subscription's activity history, which you can see in the dashboard.

## How a subscription starts

| Path | How it activates |
|---|---|
| **Checkout, free plan** | At once. No payment provider is involved. |
| **Checkout, Stripe** | When Stripe confirms the payment. Stripe then renews and charges it automatically. |
| **Checkout, ConnectIPS** | When Crovver verifies the payment with the gateway. ConnectIPS does not renew on its own: the customer pays each period through a renewal. |
| **Created in the dashboard** | **Subscriptions → Create subscription** creates it without checkout, for customers you invoice yourself, for example by bank transfer. You record its payments against its invoices in the dashboard. |

The currency is fixed when the subscription is created and never changes.

## Statuses

| Status | Meaning | Has access |
|---|---|---|
| `pending` | Created, waiting for the first payment | No |
| `trial` | In a free trial | Yes |
| `active` | Paid and current | Yes |
| `past_due` | A renewal payment failed | No |
| `pending_cancel` | Canceled, but the paid period has not ended | Yes, until the period ends |
| `canceled` | Ended | No |
| `expired` | Ended without being renewed | No |

## Renewal

- **Stripe** subscriptions renew automatically. Each successful payment starts a new period and refills the plan's credits.
- **Gateway and dashboard** subscriptions renew through a renewal invoice. The period is extended when that invoice is paid.
- A subscription can be **paid ahead** for several periods, for example a monthly plan paid for a year. Credits still refill once per period. They are not granted all at once.

## Cancellation

| Billing | What cancel does |
|---|---|
| Stripe | The subscription becomes `pending_cancel` and keeps access until the end of the period already paid. Stripe does not charge again. |
| Gateway or dashboard | The subscription is `canceled` at once. |

The customer can cancel from their billing page. You can cancel from the dashboard or from your backend with [`POST /api/public/subscriptions/{id}/cancel`](/api-reference/subscriptions/cancel).

## Changing plans

There is no in-place plan change yet. To move a customer to another plan of the same product, cancel the current subscription, then start a new one through checkout.

While a canceled Stripe subscription is still in its paid period, checkout refuses a new subscription for the same product with `409 SUBSCRIPTION_ENDING`. The customer can subscribe again once that period ends.

<Warning>
  Canceling a gateway or dashboard subscription ends it at once, and the unused part of the period is not credited back.
</Warning>

## Checking status

On the frontend, use the React SDK:

```tsx
import { useSubscription } from "crovver-react";

function Dashboard() {
  const { isActive, subscription } = useSubscription();
  if (!isActive) return <UpgradePrompt />;
  return <App renewsAt={subscription?.currentPeriodEnd} />;
}
```

On your backend, list a customer's subscriptions with the Node or PHP SDK's `getSubscriptions`, or call [`GET /api/public/subscriptions/status`](/api-reference/subscriptions/status).

To react to changes as they happen, register a webhook endpoint. See [Outgoing webhooks](/guides/outgoing-webhooks).
