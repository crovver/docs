---
title: Entitlements
description: Check if a tenant has access to a feature based on their active plan.
---

**Entitlements** are how Crovver decides whether a customer can use a feature. Crovver finds the customer's live subscription and checks whether its plan grants the feature.

## How It Works

When you call `canAccess`:

1. Crovver looks up the customer's live subscription. Pass `productSlug` if you sell more than one product.
2. It checks whether that subscription's plan grants the feature.
3. If the key is also a meter with an allowance on the plan, the customer must have credits left too.
4. It returns `canAccess: true` or `false`.

| Subscription status | `canAccess` |
|---|---|
| `trial` or `active` | `true` when the plan grants the feature |
| `pending_cancel` | `true` until the paid period ends, then `false` |
| `past_due`, `canceled`, `expired`, or no subscription | `false` |

Archiving a plan never removes access from its existing subscribers.

<Note>
  Feature keys created in the dashboard use hyphens, such as `data-export`. Pass the key exactly as it appears under **Product catalog → Catalog → Features**.
</Note>

## Checking Access — Frontend

Use the `useFeatureAccess` hook:

```tsx
import { useFeatureAccess } from 'crovver-react';

function ExportButton() {
  const { hasAccess, redirectToUpgrade } = useFeatureAccess('data-export');

  if (!hasAccess) {
    return <button onClick={redirectToUpgrade}>Upgrade to Export</button>;
  }

  return <button onClick={exportData}>Export</button>;
}
```

## Checking Access — API

```bash
POST /api/public/can-access
x-public-key: pk_live_...
Content-Type: application/json

{ "requestingEntityId": "workspace_123", "featureKey": "data-export" }
```

```json
{
  "success": true,
  "data": {
    "canAccess": true,
    "featureKey": "data-export",
    "requestingEntityId": "workspace_123"
  }
}
```

A frontend check only hides UI. Repeat the check on your backend before doing the protected work, with `canAccess` from the Node or PHP SDK and your secret key.

## Blocking UI with FeatureGuard

The `<FeatureGuard>` component handles the gate declaratively:

```tsx
import { FeatureGuard } from 'crovver-react';

<FeatureGuard
  featureKey="advanced-reporting"
  fallback={<UpgradePrompt />}
>
  <AnalyticsDashboard />
</FeatureGuard>
```

## Metered / Credit-Based Limits

Entitlements handle boolean feature access. For **consumable resources**, such as API calls, AI tokens or SMS messages, use credits instead:

1. **Check balance** before the action — [`GET /api/public/credits/balance`](/api-reference/credits/balance)
2. **Consume credits** after the action — [`POST /api/public/credits/consume`](/api-reference/credits/consume) (idempotent)

```bash
# 1. Read balance
GET /api/public/credits/balance?tenantId=workspace_123

# 2. Consume
POST /api/public/credits/consume
{
  "tenantId": "workspace_123",
  "poolKey": "api_calls",
  "amount": 1,
  "idempotencyKey": "consume-1778423112701"
}
```

See [Credits](/concepts/credits) for the full model.
