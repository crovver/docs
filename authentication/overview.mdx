Your app talks to Crovver with two kinds of key. Both are created in the dashboard under **Developers → API Keys**.

| Key | Prefix | Used from | Sent as |
|---|---|---|---|
| Public key | `pk_live_` | The browser, through the React SDK | `x-public-key` header or `?publicKey=` |
| Secret key | `sk_live_` | Your backend, through the Node or PHP SDK | `Authorization: Bearer sk_live_…` |

## Which key to use

<AccordionGroup>
  <Accordion title="Calling from the browser">
    Use the **public key**. It can read a customer's subscription status, check feature access and credit balances, list add-ons, and start checkout or the billing page. It cannot create customers, consume credits or cancel anything.

    ```tsx
    <CrovverProvider config={{ publicKey: "pk_live_…", tenantId: workspace.id }}>
    ```
  </Accordion>

  <Accordion title="Calling from your backend">
    Use the **secret key**. It can do everything the API offers. Keep it on the server only.

    ```bash
    Authorization: Bearer sk_live_…
    ```
  </Accordion>
</AccordionGroup>

A public key sent to a backend-only endpoint is refused with `401`, even in the `Authorization` header.

## Testing

Every key has the `live` prefix. Whether a payment is real depends on the payment provider credentials you connect, not on the key. To test without real charges, see [Test mode](/guides/test-mode).

## Rotating keys

You can have several keys at once. To rotate one, create a new key, deploy it, then **Disable** or **Revoke** the old key. A disabled key can be enabled again. A revoked key stops working for good.
