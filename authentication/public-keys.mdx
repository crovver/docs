title: Public keys
description: The browser-safe key the React SDK uses.
---

A public key identifies your organization from browser code. It is safe to ship in your frontend bundle.

```
pk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## What a public key can do

| Endpoint | What it does |
|---|---|
| `POST /api/public/auth/checkout-token` | Starts hosted checkout |
| `POST /api/public/auth/portal-token` | Opens the customer's billing page |
| `GET /api/public/subscriptions/status` | Reads a customer's subscription status |
| `GET /api/public/can-access` | Checks a feature |
| `GET /api/public/credits/balance` | Reads credit balances |
| `GET /api/public/tenants/{id}/addons/available` | Lists add-ons the customer can buy |
| `GET /api/public/tenants/{id}/addons/active` | Lists the customer's add-on credits |

Every other endpoint needs a [secret key](/authentication/api-keys) and refuses a public key with `401`.

Because the browser decides which customer ID it sends, treat these reads as hints for your UI. Before doing protected work, check access again from your backend with the secret key.

## Usage

The React SDK sends the key for you:

```tsx
<CrovverProvider
  config={{
    publicKey: process.env.NEXT_PUBLIC_CROVVER_PUBLIC_KEY!,
    tenantId: workspace.id,
  }}
>
```

To call an endpoint directly, send it as a header or a query parameter:

```bash
GET /api/public/can-access?featureKey=data-export&requestingEntityId=workspace_123
x-public-key: pk_live_...
```

## Billing page sign-in

A public key can open the billing page for any customer ID, so the billing page asks the customer to prove who they are. It emails a one-time sign-in link to the customer's billing email before it shows invoices or allows a cancellation. You don't need to do anything for this, beyond giving each customer an email. See [Customers](/concepts/tenants#the-billing-email).

## Creating keys

In the dashboard, go to **Developers → API Keys**. Your first public and secret keys are shown when you create your organization.
