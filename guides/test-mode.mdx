title: Test mode
description: Run the full checkout and billing flow without real charges.
---

Whether a payment is real depends on the payment provider credentials your organization is connected to. Crovver keys always start with `pk_live_` and `sk_live_`, so there is no separate test key to switch to.

## Use a separate test organization

The simplest setup keeps test data apart from production:

1. Create a second organization, such as "Acme (test)". You can switch between organizations from the dashboard sidebar.
2. Build the same products and plans there. Use the same feature and meter keys as production, so your code works against both.
3. Connect Stripe with your **Stripe test keys** (`sk_test_…` and `pk_test_…`).
4. Use that organization's public and secret keys in your development and staging environments.

Checkouts in the test organization go through Stripe's test mode, so no card is charged. When you go live, swap in the production organization's keys.

## Stripe test cards

| Card number | Result |
|---|---|
| `4242 4242 4242 4242` | Payment succeeds |
| `4000 0000 0000 0002` | Card declined |
| `4000 0025 0000 3155` | Requires 3D Secure |
| `4000 0000 0000 9995` | Insufficient funds |

Use any future expiry date and any 3-digit CVC.

## Stripe webhooks while testing

Crovver registers its Stripe webhook when you connect your test keys, so test payments activate subscriptions on their own. Nothing runs on your machine for this.

If the provider card shows **Webhook setup needed**, add the endpoint by hand. See [Payment provider webhooks](/guides/webhooks#do-i-need-to-configure-anything).

## Receiving Crovver's webhooks locally

To receive [outgoing webhooks](/guides/outgoing-webhooks) on your laptop, expose your local server with a tunnel such as ngrok, and register the tunnel's HTTPS URL as an endpoint in the test organization.

## Free plans and manual subscriptions

You don't need a payment provider to test everything else. A free plan activates at once at checkout. From the dashboard you can also create a subscription for a test customer directly, with **Subscriptions → Create subscription**, then exercise feature gates, credits and seats against it.
